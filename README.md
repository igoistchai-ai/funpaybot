# FUNPAY LISTER by nezzx

Публичный Telegram-бот для подготовки черновиков объявлений FunPay. Все пользователи могут создавать и управлять своими черновиками. В `bot.py` встроены семь изображений.

## Добавлено: подключение FunPay на сервере

- `/connect` выдаёт одноразовую ссылку на HTTPS-форму сервиса (15 минут).
- Данные вводятся в форме, а не Telegram-сообщением.
- Сервер запускает Chromium/Playwright и пытается выполнить вход на официальной странице FunPay.
- Пароль не записывается в SQLite и не выводится в логах.
- Успешное состояние браузерной сессии шифруется Fernet перед сохранением в SQLite.
- `/status` показывает сохранённый статус; `/disconnect` удаляет сохранённую сессию.
- CAPTCHA, 2FA и другие проверки могут заблокировать автоматический вход. Реальный вход с вашим аккаунтом в этой среде не тестировался.

**Важно:** пароль передаётся через ваш Render-сервис для выполнения попытки входа. Вводи его только если доверяешь владельцу и инфраструктуре этого сервиса. Одноразовая ссылка является секретом: не пересылай её. Подключение сессии само по себе не включает автопубликацию лотов; эта функция в проекте не реализована. Если FunPay изменит форму входа или запретит автоматизацию, потребуется обновление кода.

## Файлы

- `bot.py` — Telegram-бот и HTTP-сервер для Render.
- `funpay_auth.py` — логика попытки входа, одноразовые токены, шифрование и хранение сессий.
- `requirements.txt` — зависимости, включая Playwright и Fernet.
- `render.yaml` — единый сервис Render с командой установки Chromium.
- `.env.example` — пример переменных окружения.

## Локальный запуск

Python 3.11+:

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
cp .env.example .env
```

Заполни `TELEGRAM_BOT_TOKEN` в `.env`. Создай Fernet-ключ:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Скопируй его в `SESSION_ENCRYPTION_KEY`. Затем запусти:

```bash
python bot.py
```

Локально команда `/connect` не сформирует публичный HTTPS URL; для самого подключения нужен публичный HTTPS-домен.

## Render: один сервис

1. Загрузить весь каталог проекта в один GitHub-репозиторий.
2. В Render выбрать **New → Blueprint** и подключить репозиторий с `render.yaml`.
3. В Render → Environment задать:
   - `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
   - `SESSION_ENCRYPTION_KEY` — Fernet-ключ из команды выше.
   - `DATABASE_PATH` Blueprint выставляет в `data/funpay_lister.sqlite3`.
4. Build command: `pip install -r requirements.txt && playwright install --with-deps chromium`.
5. Start command: `python bot.py`.
6. Health check path: `/healthz`.

Render автоматически задаёт `PORT` и `RENDER_EXTERNAL_URL`. После запуска отправь боту `/start`, затем `/connect`.

## Хранение и ограничения

Сессии хранятся в SQLite в зашифрованном виде. На бесплатном Render локальная файловая система не гарантирует сохранность данных при повторном деплое/пересоздании экземпляра; чтобы не потерять подключения, нужна постоянная БД/диск и резервное хранение `SESSION_ENCRYPTION_KEY`. Если ключ шифрования потерян или изменён, ранее сохранённые сессии нельзя расшифровать.

Playwright использует headless Chromium на Render. FunPay может требовать CAPTCHA, одноразовый код или другую проверку, которую этот вариант автоматически пройти не сможет. Мы не обходим проверки сайта. Публикация лотов и проверка, что сессия продолжает быть действующей спустя время, пока не реализованы.

## Безопасность

- Не публикуй `.env` и не помещай секреты в GitHub.
- Не присылай Telegram bot token, пароль FunPay, `golden_key`, cookies или содержимое сессии в чат.
- Для отключения подключённой сессии используй `/disconnect`.
- Если подозреваешь компрометацию, измени пароль FunPay, отзови активные сессии на стороне FunPay и замени `SESSION_ENCRYPTION_KEY` (замена ключа сделает существующие сессии нечитаемыми).
